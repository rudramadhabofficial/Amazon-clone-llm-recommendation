# Amazon Clone & Recommendation Engine Benchmark

This project is an Amazon-inspired web application that implements and compares different product recommendation strategies. It features a responsive UI built with HTML, CSS, and Vanilla JavaScript, alongside a comprehensive Python benchmarking suite for evaluating recommendation algorithms.

## Overview

The core objective of this project is to compare traditional Machine Learning recommendation methods (K-Means Clustering and Vector Similarity) against modern Large Language Model (LLM) approaches (Llama 3.1 8B and Llama 3.3 70B via Groq API). 

The web interface allows users to search for products and view side-by-side recommendations generated by these distinct methods in real-time.

## Features

### Web Application
- **Amazon Clone Home Page (`index.html`)**: A visually appealing, responsive product catalog page that loads data dynamically from a CSV dataset.
- **Search & Recommendation Engine (`search.html`)**: 
  - Takes a search query (product name) and fetches real-time recommendations.
  - **Cluster Recommendations**: Uses pre-computed K-Means cluster labels or falls back to Cosine/Jaccard similarity on product title vectors.
  - **Llama 8B Recommendations**: Queries the Groq API (`llama-3.1-8b-instant`) to fetch context-aware semantic recommendations.
  - **Llama 70B Recommendations**: Queries the Groq API (`llama-3.3-70b-versatile`) for high-quality semantic recommendations.
  - **Side-by-Side Comparison**: Displays recommendations from all three methods side-by-side for easy qualitative comparison.

### Benchmarking Suite
- **Jupyter Notebook (`All_codes (1).ipynb`)**: A robust Python evaluation script to systematically benchmark the recommendation methods.
- **Metrics Evaluated**:
  - Precision@k
  - Recall@k
  - Mean Reciprocal Rank (MRR)
  - Normalized Discounted Cumulative Gain (nDCG@k)
  - Latency (ms)
- **Visualizations Generated**:
  - Precision and Recall Comparison bar charts.
  - MRR & nDCG comparison charts.
  - Latency distribution box plots (Clustering vs. LLM).
  - Latency vs. Precision trade-off scatter plots.
  - Metric heatmaps.

## Architecture & Tech Stack

- **Frontend**: HTML5, Vanilla CSS, Vanilla JavaScript.
- **Data Parsing**: [PapaParse](https://www.papaparse.com/) for client-side CSV parsing.
- **Backend/APIs**: [Groq API](https://groq.com/) for lightning-fast LLM inference.
- **Benchmarking / Data Science**: Python, Pandas, NumPy, Matplotlib, Scikit-learn (in Jupyter Notebook).

## Dataset

The application expects a dataset located at `assets/dataset/your_dataset_with_clusters.csv` containing e-commerce product information. Required fields include:
- `title`: Product name
- `stars`: Product rating
- `reviews`: Number of reviews
- `price`: Product price
- `categoryName`: Product category
- `title_vector`: Pre-computed vector embeddings (JSON array string)
- `relative_cluster`: Pre-computed K-Means cluster ID

## How to Run

### Web Interface
Since the application relies on fetching local CSV files and making external API calls, it is recommended to serve it over a local HTTP server to avoid CORS issues.

1. Navigate to the project directory:
   ```bash
   cd path/to/amazon
   ```
2. Start a local server:
   ```bash
   # Using Python 3
   python -m http.server 8000
   ```
3. Open your browser and go to `http://localhost:8000/index.html`.

*(Note: The `search.html` file contains a Groq API key embedded in the JavaScript. In a production environment, this should be moved to a secure backend.)*

### Benchmarking Suite
1. Ensure you have Python installed along with Jupyter Notebook and the required libraries (`pandas`, `numpy`, `matplotlib`, `scikit-learn`).
2. Open the notebook:
   ```bash
   jupyter notebook "All_codes (1).ipynb"
   ```
3. Run the cells to generate the evaluation metrics and visualization plots.

## Key Findings

Through the benchmarking suite, you can observe the trade-offs between traditional clustering and LLMs:
- **Clustering/Vector Similarity**: Offers extremely low latency and deterministic results, but may miss nuanced semantic relationships.
- **LLM Recommendations**: Provides highly context-aware and semantic recommendations, but incurs higher latency and relies on external API calls. The Llama 70B model generally yields higher quality semantic matches than the 8B model.
